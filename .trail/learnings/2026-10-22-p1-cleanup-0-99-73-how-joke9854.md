## Decided
- P1 landed as 13 commits on beta-testing after a3beac6: dead code, 118 unused strings, shared helpers (data/remote/TmdbImages.kt tmdbImageUrl, data/remote/AppJson.kt, UiDateFormatters.shortDate/shortDateTime/of(locale), ui/RelativeTime.kt elapsedSince), !! outside sync, collectAsStateWithLifecycle in DetailScreens, ui/ViewModelFactories.kt viewModelFactoryOf, theme imports, errorprone-annotations dropped, then move-only splits of LibrarySettingsScreens, DetailScreens, ProgressScreen, Components and AppDatabase DAOs.
- Splits only move code; private becomes internal where a declaration is used across the new files. DetailScreens' private Accent/AccentLight getters are copied into each Detail file instead of widened.
- AppPreferences effectiveConnectionId!! kept on purpose (provider-instance code).
## Tried and ruled out
- Making the Detail Accent getter internal: CardAppearanceSettings and StreamingSettingsScreens star-import com.cinetrack.ui.theme.*, and a same-package declaration beats a star import, so their Accent would silently switch to the poster accent.
- Dropping errorprone-annotations is safe: proguard-rules.pro already -dontwarns the four annotations; the R8 preview build passes.
## Watch out
- Every big screen file starts with @file:OptIn(ExperimentalMaterial3Api); a new split file needs it too.
- EpisodeDetailScreen had a column-0 closing brace inside the function; brace-at-column-0 span detection cut it short. Compile after each split.
- grep for '^e:' after a gradle run piped through -q can hide compile errors; check for BUILD SUCCESSFUL.
- Running testDebugUnitTest and lintDebug in one Gradle call hit Windows 'insufficient system resources' file errors; run them separately after ./gradlew --stop.
- The release baseline profile still names the old file classes (ProgressScreenKt etc.); regenerate it before 0.99.73 ships.
- On PATH, adb is an old 1.0.32; use the SDK adb at %LOCALAPPDATA%/Android/Sdk/platform-tools.
